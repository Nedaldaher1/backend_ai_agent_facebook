# خطة الـ Backend + Frontend — طبقة التحكم (Control Plane)

تبني الآن طبقة البيانات ولوحة التحكم **قبل** الوكيل. الفكرة المعمارية: **قاعدة البيانات هي العقد** بينك وبين الوكيل — أنت (عبر لوحة التحكم) تكتب فيها، والوكيل (Mastra، لاحقاً) يقرأ منها فقط. هكذا تتحكم بكل المعلومات المهمة قبل وجود أي ذكاء.

> المعلومات المهمة التي ستُمرَّر للوكيل في النهاية هي **ثلاث فئات**، وكلها تؤلَّف من لوحة التحكم:
> 1. **كتالوج المنتجات** (يقرأه الوكيل عبر `search_products`)
> 2. **قاعدة المعرفة / FAQ** (تُحمَّل كسياق للوكيل)
> 3. **إعدادات سلوك الوكيل** (تُترجَم إلى الـ system prompt)

---

## 1. الستاك الموصى به

| الطبقة | الاختيار | لماذا |
|---|---|---|
| الإطار | **Next.js (App Router)** | تطبيق واحد للـ backend + لوحة التحكم، ومتسق مع خطة Mastra |
| ORM | **Drizzle** | الأخف والأكثر توافقاً مع Postgres (مصفوفات + JSONB)، تحكّم SQL، أمان أنواع |
| القاعدة | **PostgreSQL محلي** (Docker) | نفس قاعدة الإنتاج لاحقاً (تبديل سطر واحد) |
| الطفرات (Mutations) | **Server Actions** | النمط الحديث في App Router للنماذج والأزرار |
| الواجهة | **shadcn/ui + Tailwind** | مكوّنات جاهزة، RTL سهل، سرعة بناء |
| المصادقة | **Auth.js** (أو مدير واحد بسيط) | تكفي حماية لوحة تحكم بمستخدم/مستخدمَين |

**كسب سريع:** `drizzle-kit studio` يعطيك واجهة GUI فورية لقاعدة البيانات — استخدمها لإدارة البيانات وأنت تبني اللوحة المخصّصة، فلا تنتظر اكتمال الواجهة لتبدأ بإدخال المنتجات. (بدائل لو أردت توليد CRUD آلياً: Refine أو React-Admin — لكن البناء المخصّص يعطيك تحكّماً أعلى ويدعم ميزات مثل الاستخراج بالرؤية.)

---

## 2. مخطط قاعدة البيانات (القلب)

خمسة جداول تبنيها الآن (راجع مخطط الـ ERD المرفق للصورة الكاملة):

### أ. `products` — الكتالوج (الجدول الأهم)

```ts
// src/db/schema.ts
import { pgTable, uuid, text, numeric, boolean, jsonb, timestamp } from 'drizzle-orm/pg-core'

export const products = pgTable('products', {
  id: uuid('id').primaryKey().defaultRandom(),
  name: text('name').notNull(),
  description: text('description'),
  sku: text('sku').unique(),
  priceJod: numeric('price_jod', { precision: 10, scale: 3 }).notNull(),
  colorFamily: text('color_family'),    // مُقنّن: أحمر/أسود/كحلي — مفهرس للبحث
  colorShade: text('color_shade'),      // الدرجة: نبيتي/عنابي
  sleeveType: text('sleeve_type'),
  fabric: text('fabric'),
  embellishment: text('embellishment'), // مطرّز/حجر/سادة
  occasion: text('occasion'),
  sizes: text('sizes').array(),         // مقاسات متوفرة
  stockStatus: text('stock_status').default('in_stock'), // in_stock/low/out
  imageUrls: text('image_urls').array(),
  tags: text('tags').array(),
  attributes: jsonb('attributes'),      // صفات مرنة إضافية (من الرؤية لاحقاً)
  isPublished: boolean('is_published').default(false), // هل يعرضه الوكيل
  createdAt: timestamp('created_at').defaultNow(),
  updatedAt: timestamp('updated_at').defaultNow(),
})
```

ضع فهرساً على `color_family` و`is_published` و`stock_status` — هي أكثر ما يُفلتَر عليه.

### ب. `color_synonyms` — تطبيع الألوان للهجة

`term` (نبيتي) → `canonical_family` (أحمر). يقرأه البحث ليحوّل كلام الزبون لعائلة لون مُقنّنة، فيشتغل "كل العبايات الحمراء" مهما كانت الدرجة. قابل للتعديل من اللوحة.

### ج. `agent_behavior` — "كيف يرد" (صف واحد فعّال)

الحقول: `persona`، `tone` (اللهجة)، `rules` (القواعد + الحواجز)، `greeting`، `fallback_message`، `escalation_triggers` (jsonb)، `is_active`. هذه الحقول تُجمَّع لاحقاً في الـ `instructions` (الـ system prompt) للوكيل — أي أنت تتحكم بشخصيته دون لمس الكود.

### د. `knowledge_entries` — قاعدة المعرفة / FAQ

الحقول: `category` (faq/policy/shipping/payment/about)، `title`، `content`، `tags[]`، `is_published`، `priority`. المنشور منها يُحمَّل كسياق معرفي للوكيل (سياسات، شحن، دفع عند الاستلام...).

### هـ. `admin_users` — المصادقة

`email`، `password_hash`، `role`. مستخدم واحد يكفي للبداية.

> **مؤجّل لمرحلة الوكيل (لا تبنه الآن):** جدولا `conversations`/`messages` (ذاكرة المحادثات) و`orders`/`leads` (مسودّات الدفع عند الاستلام) — يأتيان مع Mastra ولا يخصّان طبقة التحكم.

## 3. الـ Backend (الطبقات)

1. **Schema + Migrations:** عرّف الجداول في Drizzle، ثم `drizzle-kit generate` و`migrate`.
2. **طبقة الاستعلام** (`src/db/queries.ts`): دوال مكتوبة الأنواع — `listProducts(filters)`, `getProduct(id)`, `createProduct`, `updateProduct`, `deleteProduct`, `togglePublish`؛ ومثلها لبقية الجداول.
3. **Server Actions** (`app/admin/**/actions.ts`): تستدعي طبقة الاستعلام عند الإرسال من النماذج.
4. **التحقّق (Validation):** مخططات **zod** لكل كيان. مهم: نفس مخططات zod هذه ستُغذّي `inputSchema` لأدوات الوكيل لاحقاً — فتعريفها مرة واحدة هنا يوفّر تكراراً.
5. **الصور (محلياً الآن):** رفع إلى مجلد محلي وتخزين المسار في `image_urls`. لاحقاً → R2/Cloudinary بتغيير دالة الرفع فقط.
6. **(اختياري) استخراج بالرؤية:** زر في نموذج المنتج "استخراج الصفات من الصورة" ينادي Claude لاقتراح اللون/الكم/القماش تلقائياً. يمكنك إضافته الآن (Claude متاح) أو إدخال الصفات يدوياً وتأجيله — طبقة التحكم تعمل بدونه.

## 4. الـ Frontend (لوحة التحكم — الشاشات)

راجع خريطة الشاشات المرفقة. الشاشات الأساسية:

- **تسجيل الدخول** — حماية اللوحة.
- **المنتجات:** قائمة بجدول + بحث وفلترة (لون/مخزون/منشور)؛ ونموذج إنشاء/تعديل فيه كل الصفات + رفع صور + زر الاستخراج بالرؤية (اختياري) + مفتاح النشر.
- **الألوان والمرادفات:** محرّر خريطة `نبيتي → أحمر`.
- **سلوك الوكيل:** نموذج لتحرير الشخصية + النبرة + القواعد + الترحيب + الرد الاحتياطي + محفّزات التصعيد.
- **قاعدة المعرفة / FAQ:** قائمة + إنشاء/تعديل (فئة، عنوان، محتوى، نشر).
- **(لاحقاً) سجل المحادثات:** مع مرحلة الوكيل.

---

## 5. كيف يقرأ الوكيل لاحقاً (العقد)

عند بناء Mastra، أدواته تقرأ هذه الجداول **للقراءة فقط** دون تغيير المخطط:

- `search_products` → يقرأ `products` (يُطبّع اللون عبر `color_synonyms`، ويُظهر `is_published = true` فقط).
- سياق المعرفة → `knowledge_entries` المنشورة.
- الـ system prompt → يُجمَّع من `agent_behavior`.

أي: لوحة التحكم = جهة **الكتابة**، الوكيل = جهة **القراءة**، وقاعدة البيانات بينهما. تبني طبقة التحكم كاملة الآن، ويتّصل الوكيل لاحقاً بلا أي تعديل على البنية.

---

## 6. ترتيب بناء هذه المرحلة

1. **Postgres (Docker) + Drizzle + Schema + أول migration** — تحقّق عبر Drizzle Studio.
2. **طبقة الاستعلام + مخططات zod.**
3. **المصادقة + هيكل اللوحة (layout + حماية).**
4. **CRUD المنتجات** (أكبر شاشة): قائمة + نموذج + رفع صور.
5. **محرّر الألوان والمرادفات.**
6. **محرّر سلوك الوكيل.**
7. **قاعدة المعرفة / FAQ.**
8. **(اختياري) زر الاستخراج بالرؤية** في نموذج المنتج.

بعدها تكون طبقة البيانات والتحكم جاهزة بالكامل، ويصبح بناء وكيل Mastra مجرد "توصيل قارئ" بها.

---

## 7. المؤجَّل (Phase لاحقة)

جداول المحادثات والطلبات، النشر السحابي، تخزين الصور الخارجي، والـ debounce — كلها لاحقاً. ركّز الآن على المخطط + اللوحة حتى تمسك كل المعلومات التي سيعتمد عليها الوكيل.

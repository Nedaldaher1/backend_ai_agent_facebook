## 1. شو هذا المشروع باختصار

هذا **الـ Backend** لوكيل مبيعات ذكي يردّ على رسائل زبونات صفحة عبايات **ماسة** على فيسبوك. الوكيل لازم:

- يردّ باللهجة الأردنية العامية بصوت البراند (شخصية البياعة "لمى").
- يبحث بالكتالوج بالصفات (لون، مقاس، قماش، مناسبة) **وبالصور** اللي بتبعتها الزبونة.
- يحفظ سياق المحادثة ويعرف من أي إعلان إجت الزبونة.
- **ما يخترع أسعار ولا توفّر** — بس يحكي حقائق من قاعدة البيانات.
- يلتقط طلبات الدفع عند الاستلام (COD) ويحوّل لإنسان وقت الحاجة.

هذا الريبو هو **الـ Backend بس**. لوحة التحكم (Next.js) وتكامل فيسبوك (Meta Graph API) مواضيع منفصلة. القاعدة هي مصدر الحقيقة الوحيد: لوحة التحكم بتكتب فيها، والوكيل بيقرأ منها.

> **ملاحظة مهمة:** قسم §2c بملف `CLAUDE.md` بيقول إن الريبو "greenfield scaffold" فاضي — **هذا الكلام قديم ومش صحيح**. المشروع شبه مكتمل (205 ملف TypeScript، 875 اختبار ناجح).

## 2. الستاك التقني

| الطبقة | التقنية |
|--------|---------|
| Runtime / Package manager | **Bun** (مش pnpm — راجع المطبّات) |
| Framework | NestJS 11 + **Fastify** adapter (مش Express) |
| ORM | Drizzle ORM 0.45 |
| قاعدة البيانات | PostgreSQL (محلي بالتطوير عبر WSL) + امتداد `pgvector` للبحث البصري |
| تنسيق الـ AI | **Mastra** 1.42 |
| المزوّد (LLM) | **OpenRouter → Google Gemini 3.5 Flash** (الوكيل والرؤية) |
| الـ Embeddings | **google/gemini-embedding-2** عبر OpenRouter (متعدد الوسائط، بُعد 1536) |
| التحقق | zod + class-validator |

الوحدات ESM (`module: nodenext`)، ومسارات الـ alias (`@/...`) بتنعاد كتابتها وقت البناء بـ `tsc-alias`.

## 3. بنية المشروع (الوحدات)

كل وحدة تحت `src/modules/<domain>/` فيها: `*.entity.ts` (جداول Drizzle)، `*.repository.ts` (وصول للقاعدة، بدون SQL خام)، `*.service.ts` (منطق)، `*.controller.ts` (REST)، و`tests/`.

| الوحدة | المسؤولية |
|--------|-----------|
| `products` | الكتالوج: المنتجات، الألوان ومرادفاتها، صور المنتج وألوانها لكل صورة، أوصاف الصور، الـ embeddings، ربط الإعلان بالمنتج. |
| `orders` | طلبات COD وعناصرها، رسوم التوصيل، صياغة الهاتف، حالات الطلب. |
| `conversations` | المحادثات، الرسائل، أحداث المحادثة، خدمة التحكم (reset / pause / handoff). |
| `knowledge` | مدخلات المعرفة (FAQ) اللي بيسحبها الوكيل كـ RAG. |
| `sizing` | جدول المقاسات (تحويل الوزن لرمز مقاس). |
| `admin` | مستخدمو لوحة التحكم. |
| `auth` | تسجيل الدخول (JWT)، التسجيل خلف فلاغ `ALLOW_REGISTRATION`. |
| `embeddings` | توليد embeddings للصور (عبر Gemini). |
| **`agent`** | **قلب المشروع** — وكيل Mastra، الأدوات، الذاكرة، الرؤية، قناة Messenger، الـ debounce. |

طبقات أساسية تحت `src/core/`: `database` (Drizzle)، `config` (مخطط البيئة zod)، `storage` (flydrive)، `security`، `health`، `openapi`.

## 4. قاعدة البيانات

**16 جدول** معرّفة كـ entities، و**16 هجرة** تحت `drizzle/` (آخرها `0015_confused_marauders.sql`).

- **جداول التحكم (لوحة التحكم بتكتب، الوكيل بيقرأ):** `products`, `colors`, `color_synonyms`, `product_image_colors`, `product_image_descriptions`, `product_image_embeddings`, `ad_product_links`, `agent_behavior`, `knowledge_entries`, `size_chart`, `admin_users`.
- **جداول الوقت الفعلي (الوكيل بيكتب):** `conversations`, `messages`, `conversation_events`, `orders`, `order_items`.

قواعد ثابتة:
- `is_published` هي بوابة النشر: مسارات الزبون والوكيل لازم تفلتر `is_published = true`.
- الفلوس `numeric(10,3)` للدينار — **ممنوع** floating-point على الأسعار.
- البحث باللون بيمرّ عبر `color_synonyms` (مثال: "نبيتي" → عائلة الأحمر).
- جداول Mastra (الذاكرة) بـ schema منفصل اسمه `mastra` (مش `public`)، و`drizzle.config.ts` مقيّد على `public` بس.

> **تنبيه:** القاعدة المحلية بتتأخّر عن الهجرات أحيانًا → خطأ 500 وقت التشغيل "column does not exist". الحل: `bunx drizzle-kit migrate`.

## 5. الوكيل (Mastra) — قلب النظام

ملف `src/modules/agent/agent.service.ts` فيه التدفّق الرئيسي `handleMessage()`:

1. **Dedup** للرسائل المكررة.
2. فحص حالة المحادثة `ai_state`: لو `human`/`paused` → يسجّل الرسالة الواردة ويسكت (ما يشغّل `generate()`).
3. لو في صورة من الزبونة → خط الرؤية (`vision.service`) يستخرج صفاتها.
4. **Knowledge prefetch:** يحلّ المنتج (صورة / آخر منتجات / منتج الإعلان) ويحقن الـ FAQ تبعه بالسياق قبل `generate()`.
5. يسجّل سجل العمل بجدول `public.messages` **قبل وبعد** التوليد.
6. ينادي `salesAgent.generate()` مع scoping للذاكرة و`requestContext` (الهوية).

**الأدوات الـ 11** (تحت `tools/`، كل أداة "thin adapter" بتنادي خدمة، بدون SQL):

- **الذاكرة:** `@mastra/memory` + `@mastra/pg` (جداول `mastra_threads/messages/resources`). الهوية: `resourceId`/`threadId` من `contact_id`.

## 9. مطبّات معروفة (لا تنساها)

- **Bun مش pnpm:** الـ apps بتستورد `fastify` غير معلَن؛ bun بيرفعه (build OK)، pnpm الصارم بيكسر (TS2307).
- **الوكيل صار على OpenRouter/Gemini 3.5 Flash** (مش Claude). `OPENROUTER_API_KEY` صار مطلوب، و`ANTHROPIC` اختياري.
- **رسوم التوصيل ثابتة:** 2.000 دينار، بدون شرائح حسب المحافظة (رغم ما تقوله بعض المواصفات).
- **رموز المقاسات `1`/`2`** بتنحسب من الوزن عبر `size_chart`.
- **`knowledge_entries` فيها 0 صف عام** → الأسئلة العامة بتتحوّل لإنسان لحد ما تضيف الأدمن مدخلات.
- **القاعدة المحلية بتتأخر عن الهجرات** → شغّل `drizzle-kit migrate`.
- **Linear:** البادئة `AIA` (مثال `AIA-36`)، الفريق "ai agent"، الـ slug `saletna`. فريق "Saletna" التاني **ممنوع تلمسه** (§7).
- **بيئة الساندبوكس بتحذف عبارة "أهلين والله"** من الملفات وقت الكتابة (مشكلة ساندبوكس بس، مش الريبو/الإنتاج) — استعمل أهلين/مرحبا.
- **`source .env` بينكسر** على سطر `ANTHROPIC_API_KEY` (في مسافة قبل `=`؛ dotenv بيشيلها بس الـ shell لأ).
